## 1. Chosen approach and why

**What exists today (verified in code):**
- Hero v2 = `hero_meshy3` (`kingdom/scripts/actors/player.gd:467-480`, `TIER_A_PATH`), a single-atlas Meshy body (4.2k tris, one `hero_character.gdshader` material, head is part of `*base_body*` mesh, `head_rigid_verts: 640`). It has **no face blendshapes**. The only face geometry is a `Lids` patch mesh (built by `tools/blender/hero_tier_a/hero_fix.py`, shape key `Blink`, visible only while blinking, shader `kingdom/shaders/hero/hero_lid.gdshader`).
- `kingdom/scripts/actors/hero_face_driver.gd` (CRLF file) already does blink (2-6 s, double blink), `talk(seconds)` jaw flap envelope and `set_expression("Smile"|"Jaw_Open"|"Brow_Up")` — but on the Meshy hero `_face` is null, so **only the Lids blink has any visible effect**. `HeroTierA.dress_meshy_hero()` (`kingdom/scripts/actors/hero_tier_a.gd:~300`) creates the driver with `parts = {"Lids": ...}` only.
- `hero_character.gdshader` already paints **brow UV rects** of the 2048 atlas: `x 750-815, y 510-610` and `x 440-500, y 1335-1372` (`brow_lift`). That is the only face UV region known. Eye/mouth rects are NOT known.
- The hero's body material is **shared** through `HeroTierA._char_mats` (keyed by texture); `dress_meshy_hero` only duplicates it when a creator `look` is passed.
- Villagers: `kingdom/scripts/population/villager.gd` (LF) already has a `LookAtModifier3D` on `Head` (`_add_head_look` line 1454, `_update_head_look` line 1478: player in talk or < 5 m, else `_partner_node`, else `_look_point`, else LifeAmbience `_amb_look`). `CrowdAnimLOD` (`kingdom/scripts/living_world/crowd_anim_lod.gd`) turns the modifier on only in NEAR tier (`lod_tier == 0`, at most `near_max` = 3/5/8/12 bodies within 10/12/14/18 m by tier) — **gaze is already done and already budgeted**.
- Villager bodies are heterogeneous (MakeHuman `villager_man_a`…, G6 modular with separate `_head_` meshes, Meshy3 painted single-atlas), merged into ONE surface with ONE **cached, shared** `StandardMaterial3D` (`kingdom/scripts/world/character_merge.gd`, tinted copies cached per colour in `TownIdentity.tint_model`). No blendshapes, no per-NPC material. A shader-rect approach is impossible for villagers.
- Dialogue: Dialogue Manager addon is installed but **unused**; lines are JSON via `kingdom/scripts/sim/dialogue_runner.gd` (`pick_line` returns `{text, do}`), shown by `kingdom/scripts/world/village_services.gd:_enter(node)` (line ~1388) and the choice callback `_choose(c)`; the world side is `kingdom/scripts/ui/talk_session.gd` which calls `npc.talk_begin(player)` / `talk_end()` and `player.set_talk_framing(on, npc)`. The talking body is found with `_npc_node(info)` (line ~1370).
- NPC mood inputs available without guessing: `villager._act` (enum `Act`: SLEEP/EAT/SOCIAL/INN/PRAY/FLEE/PROTEST/ALARM/MOURN/FESTIVE/…), `villager._mood` (TownMood dict keys `festival:String, war:float, monster:float, curfew:bool, mourning:float, scarcity:float, rest_day:bool`), and the dialogue ctx `opinion` (`_talk_ctx(info)`). UtilityBrain needs are a `PackedFloat32Array` with undocumented indices — do not use.
- Quality: `Quality.tier` (int: 0 LOW, 1 MEDIUM, 2 HIGH, 3 ULTRA), `Quality.renderer()` returns `"gl_compatibility"` on LOW phones. Instance shader uniforms do not exist in Compatibility.

**Chosen (cheapest viable) design — two thin mechanisms, one shared state machine:**

A. **`FaceState` (pure logic, `kingdom/scripts/living_world/face_state.gd`, `extends RefCounted`, no class_name)** — one per face. Inputs: `set_mood(name)`, `say(seconds)`, `step(dt) -> Dictionary {brow, lids, mouth_open, mouth_curve}`. Owns blink timer (2-6 s, 0.28 s close+open, 20% double), mouth flap (6-9 Hz sine while `say` runs), eased mood targets (0.25 s). Mood table (the 6 moods → brow/lids/mouth_curve targets) lives here. Unit-testable with no scene.

B. **Hero** — extend `HeroFaceDriver` to drive the hero's **own duplicated** `hero_character.gdshader` material with 3 new uniforms (`face_brow`, `face_mouth_open`, `face_mouth_curve`) evaluated inside the **existing UV-rect block** (brow rects known; mouth rect measured once by a probe, see step 2), plus `Lids` partial weight for squint. Zero extra draw calls, ~10 ALU, one material duplicate.

C. **Villagers** — a `FaceCard`: one `QuadMesh` (2 tris) on a `BoneAttachment3D("Head")`, one **shared** `ShaderMaterial` (`kingdom/shaders/npc/npc_face_card.gdshader`) with `instance uniform`s for brow/lids/mouth, drawing only **ink lids, brows and a mouth** (no eye whites/pupils — the painted eyes stay), alpha-scissor, unshaded-ish warm ink. Created only when `int(Quality.tier) >= 1 and Quality.renderer() != "gl_compatibility"`; visible only while `lod_tier == 0` (NEAR) and inside a 12 m `visibility_range_end`. Worst case +near_max draw calls on MEDIUM+ (5/8/12), **zero on LOW** (not created).

Why this and not alternatives: blendshape heads would need Blender re-authoring for 12+ villager looks and a new hero head (rejected by the hero README history); per-NPC shader uniforms are impossible (shared merged materials); a flipbook texture card needs painted art the agent cannot make. The procedural ink card needs no asset, 1 draw, and is gated so LOW gains nothing.

**Step 1 — `FaceState` + tests.**
New `kingdom/scripts/living_world/face_state.gd`:
- `const MOODS := ["neutral","happy","sad","angry","fear","surprise"]`
